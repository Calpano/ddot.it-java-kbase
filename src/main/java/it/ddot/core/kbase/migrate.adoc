= Migrate

cc-kg capabilities absent from our IKbase API

== IKbase level (vs IKnowledgeRoot + IKnowledgeDocumentService)

[cols="1,1",options="header"]
|===
| cc-kg | Notes

| `deleteGraph(id)` / `deleteAllGraphs()`
| No graph deletion in our API

| `exportGraph(id)` / `exportToConnectedJson()`
| No serialization/export

| `search(String query)`
| Full-text search across graphs/nodes/edges by ID and label

| `context(Map<String,String>)`
| @context namespace map (URI expansion/prefixes)

| `importCjDocument(ICjDocumentMutable)`
| Bulk import from Connected JSON

| `update(ICjDocumentChunk)` / `getState()`
| Bulk state read/overwrite

| `listGraphs()` → `Stream<String>` IDs
| Our `graphs()` returns instances directly; cc-kg separates listing from retrieval

| `createKnowledgeBase` / `deleteKnowledgeBase` / `listKnowledgeBases`
| Multi-kbase root management (our IKbase IS the kbase, no root above it)
|===

== Graph level (vs IKnowledgeGraphService)

[cols="1,1",options="header"]
|===
| cc-kg | Notes

| `delete()`
| Delete the graph itself

| `bulkDelete(String[] ids)`
| Delete multiple entities at once

| `deleteLabel()`
| Our `label()` only sets

| `mergeNodes(String[] sources, String target)`
| Merge multiple nodes into one, remapping all edges

| `update(ICjGraphChunk)` / `updateData(String)`
| Bulk state write / JSON data on the graph itself

| `getEdge(String id)`
| Our API only has `edges()` stream; no get-by-id

| `ensureNode(String id)`
| Get or create by ID (our `getOrCreateNodeWithIdAndLabel` requires a label)
|===

== Node level (vs IKnowledgeNodeService)

[cols="1,1",options="header"]
|===
| cc-kg | Notes

| `copyToGraph(String targetGraphId)`
| Copy node to another graph

| `addType(String)` / `deleteType(String)`
| RDF-style `rdf:type` management

| `delete()`
| Delete node

| `setContent(String)` / `deleteContent()`
| Separate "content" field distinct from label

| `deleteLabel()`
| Our label only sets, never clears

| `updateData(String jsonData)`
| JSON data as string (ours uses `IJsonValue`)
|===

== Edge level (vs IKnowledgeEdgeService)

[cols="1,1",options="header"]
|===
| cc-kg | Notes

| `setEdgeType(String)` / `deleteEdgeType()`
| Edge type as a first-class field (separate from endpoints)

| `setLabel` / `deleteLabel`
| Edge labels (our `IKnowledgeEdge` inherits from `IKnowledgeItem` but cc-kg makes these explicit)

| `splitEdgeType(edgeType, newTypes[])`
| Split one edge type into multiple, creating new edges

| `splitHyperedgeCentralNode(id, centralNodeId)`
| Hyperedge → binary edges via central node

| `splitHyperedgeExplosion(id)`
| Hyperedge → all pairwise combinations
|===

== Summary of biggest gaps

. No deletion anywhere (graph, node, edge, label)
. No merge/split operations (`mergeNodes`, `splitEdgeType`, `splitHyperedge*`)
. No export/import (`exportToConnectedJson`, `importCjDocument`)
. No full-text search across the knowledge base
. No node types (`addType`/`deleteType` — RDF `rdf:type`)
. No `@context` namespace map
. Node content as a separate field from label
